## 【订正】TMP 完全不用读，CMapDataExt::TileData 就是 TileCellAttr

之前判断"`hasFrame` 是逐 sub-cell 的、FA2 的 `HasValidImage` 只到 block 粒度"，**是错的**。
`CTileTypeClass` 里 `TileBlockCount` 就是 TMP 的 `cellsInX*cellsInY`，`TileBlockDatas[k]` 一个 block 对应一个 TMP 子格，所以 `HasValidImage` 本来就是逐 sub-cell 的。

逐字段对照（11 项对上 9 项）：

| `TileCellAttr` | `CTileBlockClass` / `CTileTypeClass` |
|---|---|
| `hasFrame` | `CTileBlockClass::HasValidImage` |
| `terrainType` / `rampType` | `TerrainType` / `RampType` |
| `cellsInX` / `cellsInY` | `CTileTypeClass::Width` / `Height`（**类级**，不是 block 级） |
| `extra4` / `extra24` | `XMinusExX` / `YMinusExY` |
| radar 六项 | `RadarColorLeft/Right`（`RGBClass{R,G,B}`） |
| `flags36` | 无对应，只喂 `ZAdjust`（渲染字段，用不到）→ 置 0 |

索引语义：`CMapDataExt::TileData[i]` 的 i 就是**绝对 tile index**（`InitializeTileData()` 从 `CTileTypeInfo::X().Datas` memcpy，而引擎该数组按 tile index 排）。判据是 `Body.cpp:1458`：`tileIndex - TileSet_starts[TileData[tileIndex].TileSet]` 算 set 内相对编号。

结论：`CMapGenDataFeed` 改为纯拷 `TileData`，**不再读 TMP，也不再用 `CMixFile` / `SearchFileExt`**。已重写。

## 崩溃排查（x32dbg MCP）

现场：`0xC0000005`，`fa2sp.dll+0x4307B6`，`mov edx,[eax+8]`，**eax = 0xCFCFCFC1**（堆填充值）→ 说明某个对象指针来自未初始化/越界内存。

根因（本轮新加的“生成前清空选区”）：边遍历格子边 `DeleteBuildingData/DeleteTerrainData/DeleteSmudgeData`。`DeleteXxxData` 会把数组后面的元素前移，其他格子里的 `cell->Terrain/Smudge/Structure` 仍指向旧下标；后续 `UpdateFieldTerrainData` / `UpdateFieldStructureData_Optimized` 按这些越界下标取对象，就拿到 0xCF 填充值。

修法：
1. 第一遍只**收集**待删下标，同时把格子的 `Structure/Terrain/Smudge` 立刻置 -1（切断引用）。
2. 第二遍按下标**降序**删除（低下标在删除过程中保持有效），并做去重与范围保护。

x32dbg 用法备忘：`GetDebugState` / `GetEventLog` / `GetCallStack` / `GetAllRegisters` / `ListModules`（取 base → RVA）/ `Disassemble`。

## 崩溃根因（确认）：动态步长改造漏了 50 处直接下标

现场 `fa2sp+0x4307B6`，x64dbg 标注调用点 `RandomMapGenerator::IsWaterTile+6`。崩溃指令
`mov edx,[eax+8]` 里 **eax 就是传入的 `cell`**，`[eax+8]` = `MapCell::IsoTileTypeIndex`，
`[ecx+A44]` = `waterTileIndex_` —— 也就是 IsWaterTile 的内联体本身。eax=0xCFCFCFC1 说明
调用方从**槽位数组越界**的位置读到了未初始化堆内存当作 cell 指针。

原因：改 `slotStride_` 时，第一遍 grep 只查了 `MapGen.cpp` / `MapGen.h` 两个文件，
漏掉了其余 13 个参与编译的文件里 50 处 `cellSlots_[512 * y + x]` 和 `x + (y << 9)`。
步长变成 W'+H'+1 后（例如区域模式 W'=H'=200 时数组只有 401*401），`512*350` 这种下标
直接越过数组末尾。

已全部改为 `slotStride_`（`MapGenRiver.cpp` 41 处、`MapGenLAT.cpp` 4、`MapGenMakingSub.cpp` 4、`MapGen.cpp` 1）。
唯一保留的 `<< 9` 在 `ScatterLATBlobs` 里，那是 `MapCoords` 键运算，不是槽位索引。
fork 提交 `f75eb48`。

**教训**：全局常量改成成员变量时，搜索范围必须是全部参与编译的 TU，而不是改了定义的那个文件。

## 水面/岸线问题的根因（第二处步长残留）

`TileNeighbourMask`（MapGenRiver.cpp）里 `base` 已按 `slotStride_` 计算，但**八个邻居偏移仍写死** `±512 / ±511 / ±513`。
步长一旦不是 512，掩码采样到的是无关格子 → 水面连通性判断错 → 岸线/海岸全乱。
已改为 `step = slotStride_`，八个偏移全部由 `step` 推导（`base ± step ± 1` 等）。fork 提交 `eb2e01c`。

**这是同一类错误的第二次**：上一轮正则只覆盖 `512 * ` 和 `(y << 9)`，没覆盖**裸的 ±512 偏移常量**。
以后改步长/常量，必须同时搜索：`N * `、`<< k`、`±N` 三种形态。

## 遗留（大地图相关，尚未修）

`ExpandWaterBody(genCode, mode, 0,0, 512,512, ...)` 的 `512×512` 是**坐标窗口**（`nx >= centerX + rangeX` 就跳过），
vanilla 里 512 恰好等于最大坐标，所以等价于全图。当 `W'+H'+1 > 512` 时，坐标 ≥512 的格子会被挡在水域扩张之外。
要支持 w+h 到 2048，需把这些字面量换成 `size_.workSide`，同时把 `rect[2] != 512` / `rect[3] != 512` 这两个哨兵比较一起换。
注意：直接换会让哨兵判断永远成立，必须同步改比较量。

## 岛屿形状几乎不变的成因（种子设计）

原版把地图自己的 RNG 用**常量 0** 播种（`0x58b770: push 0; mov ecx, offset dword_ABE890`），
所以地形主体（岛屿骨架、山脉走向）每次完全一致；只有 `RollGlobalOptions` 用全局种子滚出来的
水量/植被/布局参数在变，于是表现成「岛形基本不变、只有局部细节和一小段海岸线变」。
内陆/山地走 `GenerateSpecialTerrain`，对滚出来的 waterAmount 特别敏感，所以看起来每次都不同。

我在 UI 简化时删掉了“地形种子”输入并写死 `cfg.mapRngSeed = 0`，等于把岛形锁死。
现在改为**同一个种子同时喂两处**：
```cpp
const unsigned seed = req.randomSeed ? GetTickCount() : req.globalSeed;
cfg.global = rmg.RollGlobalOptions(seed);
cfg.mapRngSeed = seed;
```
即“一个数字 = 一张完整的地图”。同时 `CMapGenBridge::LastSeed()` 把实际用到的种子回填到输入框，
取消“随机”后按一次即可复现喜欢的图。

## 山地小概率崩溃：槽位数组越界（x32dbg 定位）

现场 `0xC0000005`，`mov edx,[eax+4]`，**eax = 0**，符号解析为 `RandomMapGenerator::GenerateDelta` 内联 lambda。
反汇编里能看到 `[esi+970]=cellSlots_`、`[esi+978]=slotStride_`，以及 `mov [eax+8],0xFFFF`（写 IsoTileTypeIndex）。

根因：`CellExists()` 允许 `y` 到 `W'+2H'-1`（x=1 时），但 `slotRows_ = W'+H'+1`。
边缘探针 `slotStride_*y + x` **越过数组末尾**，读到堆里的随机值 → 有时是 0 直接崩，有时是脏指针。
零售引擎不会踩到，因为它的 `Cells.Items` 就是完整的 512×512 网格。

两处修复（fork `8523aba`）：
1. `slotRows_ = W' + 2H' + 1`，让所有 CellExists 合法坐标都有槽位（菱形外仍是 nullptr，迭代器靠它终止）。
2. 新增 `MapCell* SlotOrInvalid(int)`：越界或空槽返回 `invalidCell_`；`GenerateDelta` 里 **16 处** `cellSlots_[...]->` 全部改为 `SlotOrInvalid(...)->`。

顺带修了导出：`GetSafeTileIndex(0xFFFF)` 会把“无地形”夹成 0（真实地形），
日志里 `mismatch=121 src 65535 vs dst 0` 就是它。现在 0xFFFF 原样保留。

UI：第 6 页同时禁用 `Controls::Clear`（“清除”按钮）。

## 建筑所属方按地图 [Houses] 解析

生成器把科技建筑的 owner 写死成 `Neutral House`，但地图只认自己 `[Houses]` 里有的名字。
新增 `ResolveHouseName(CINI&)`（CMapGenBridge.cpp 匿名命名空间），优先级：
`[Houses]` 为空 → `Neutral`；含 `Neutral House` → 用它；含 `Neutral` → 用它；否则用第一条。

**关键**：`[Houses]` 的格式是 `索引=名称`（`0=Americans` / `1=Neutral House`），

所以匹配的是条目的 value 而不是 key。
